# Дерево духов для Sky — нативный Windows-мод

Две DLL: `powrprof.dll` в папку игры, `SkySpiritBridge.dll` в `mods`.
Русский интерфейс на Dear ImGui, в процессе Sky. Без отдельного EXE,
.NET и каналов между процессами.

## Установка

1. Полностью закройте Sky.
2. Steam → Библиотека → Sky → Управление → Просмотреть локальные файлы.
3. Распакуйте полный архив версии 0.3.0 рядом с `Sky.exe`:

```text
Sky.exe                        ← существующая игра
powrprof.dll                   ← загрузчик
mods/
    SkySpiritBridge.dll        ← мод с интерфейсом и каталогом
```

При обновлении с нашей версии 0.2.0 удалите старый `dxgi.dll` именно из
нашего комплекта: он больше не используется. Чужие загрузчики не заменяйте.
Если `powrprof.dll` уже принадлежит другому моду, не перезаписывайте её.

На Windows запустите игру обычным способом через Steam. В Linux / Proton
потребуется переопределение `WINEDLLOVERRIDES="powrprof=n,b" %command%`
в параметрах запуска Steam либо такое же правило для Sky.exe в Wine.

## Использование

- После входа мод читает текущую сессию из игры и сам загружает каталог.
- Слева — духи и ветки событий; есть поиск по имени духа или предмета.
- Доступны фильтры новых, изменённых и удалённых предметов, типов и событий.
  Первый каталог становится отправной точкой; последующие сравниваются с предыдущим.
  Кнопка принятия базы позволяет начать сравнение заново.
- Можно переключать дерево и список, сортировать список по имени или цене.
- Справа — граф зависимостей. Карточки содержат техническое имя, цену,
  валюту, иконку и требование пропуска. Клик по карточке показывает ID и предшественника.
- «Обновить каталог» повторяет чтение; «Экспорт JSON» сохраняет полный каталог,
  независимо от поиска и выбранного духа.
- F8 скрывает/показывает панель. За верхнюю полосу её можно перемещать.

Путь экспорта:

```text
Загрузки\sky-spirit\spirit-catalog-export.json
```

Кнопка «Папка» открывает точное расположение. Папка «Загрузки» определяется
через Windows Known Folders, включая перенесённые каталоги.
Предыдущий экспорт сохраняется рядом с суффиксом `.previous`.

Дерево показывает зависимости `dep`, а не восстановленные координаты штатного
магазина. Технические имена не заменяются выдуманными переводами. Неизвестные
типы валют показываются исходным идентификатором сервера. Иконки читаются
из локальных ресурсов игры; для некоторых служебных узлов используется значок
категории. В JSON добавляются имя иконки, атлас и UV, сами изображения в архив
не включены. Расписание событий не восстанавливается;
наличие ветки в каталоге не подтверждает активность события.

Панель — принадлежащее Sky нативное ImGui-окно без отдельного приложения.
Графика D3D11 рисуется в собственную поверхность; Vulkan-путь игры не меняется.
В оконном режиме без рамки панель отображается поверх игры. Это не подмена
штатного UI магазина и не перенос всех функций Rund.

## Что изменилось относительно 0.2.0

Старая связка C# / EXE / named pipe заменена нативным модулем.
Сессия читается после штатного Game::Update, через Game.accountServerClient,
как в Rund CurrentAccount. Межпроцессного канала и проверки его PID больше нет.
Для HTTPS берётся штатный User-Agent из работающего клиента, а не строка
посторонней утилиты. Запросы игры не перехватываются и не подменяются.

Используется только `/account/get_spirit_shops`, с пагинацией `l/o/v`.
Смена сессии, каталога, повтор ID или неполный ответ отменяет обновление.
Предельный размер — 50 000 узлов. Покупки и изменения аккаунта отсутствуют.
Сертификаты TLS не подменяются, их проверка не отключается.

На диск попадают только поля каталога:
`id`, `nm`, `spirit`, `typ`, `cst`, `ctyp`, `dep`, `ap`, `evn`, `ta`,
`tt`, `to`, `td` и прежние варианты полей валюты. Дополнительно —
`icon`, `icon_atlas`, `icon_uv` из локальных ресурсов. Валюта берётся из `ctyp`:
свечи, сердца, вознесённые и сезонные валюты, билеты событий.
Ключи аккаунта не читаются; UUID и сессия не сохраняются и не логируются.
Служебный кэш и безопасные диагностические события находятся в
`%LOCALAPPDATA%\SkySpiritExport\native`.

## Сборка

Windows: x64 Native Tools Command Prompt, Visual Studio 2022 C++:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
python package.py
```

Linux: LLVM-MinGW (официальный toolchain), переменная `SPIRIT_TOOLCHAIN`
с путём к распакованному каталогу, затем `bash build-native.sh`.
Обычная сборка не содержит автоматического тестового экспорта и снимка UI;
флаг `SPIRIT_VALIDATION=1` предназначен только для локальной проверки.
Результат: `dist/native/powrprof.dll`, `dist/native/SkySpiritBridge.dll`.
GitHub Actions собирает Windows-версию и проверяет каталог и загрузчик.

Нативный каталог тестируется отдельно: пагинация, смена сессии/версии,
неполные ответы, повтор ID, ошибочные цены, неизвестная валюта, циклы и
недостающие зависимости, исключение посторонних полей.
